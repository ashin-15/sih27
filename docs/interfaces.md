# Interface and contract registry

Current contracts, checked 2026-09-29. Read source and tests before modifying
any of these. A CPU FRNet semantic predictor, bounded per-scan obstacle
candidate stage and bounded known-thing tracker are implemented. Visibility
and live-source interfaces are NOT IMPLEMENTED.

| Interface | Owner and consumers | Inputs and outputs | Invariants and compatibility | Validation |
| --- | --- | --- | --- | --- |
| CLI `drishti demo/replay` | `cli.py`; developers and report consumers | Config, `--device cpu` or `cuda`, new output directory, dataset/sequence or synthetic settings; manifest, frame JSONL, summary, optional Rerun recording. `replay --check-100ms` adds per-scan `replay-timing.jsonl` and current-result receipts. | Never write inside source dataset; output directory must be new; `--mode oracle` reads labels only for evaluation. The check paces label-free replay at 10 Hz, compares scheduled arrival to synchronous in-process receipt of the current `FrameResult` against 100 ms, and returns 2 on a miss. Report-flush age is saved separately. Report schema version 2 distinguishes this from earlier audit-flush checks. It requires `--view none`; Rerun is outside the deadline and evaluated separately. The JSONL is audit metadata and digests, not a serialized map. `--device cuda` requires a working NVIDIA device and compatible CuPy installation; CUDA projection/ownership/reductions produce the same public host result types. This is not a full-path release gate, approved product consumer or disk `fsync` proof. | `tests/test_cli.py`, `tests/test_output.py`, `tests/test_cuda_backend.py`; [O-001 output audit](o-001-output-boundary-audit.md). |
| Diagnostic in-process frame consumer | `output.py`; paced CLI replay | Current `ScanFrame` and `FrameResult` -> synchronous `FrameReceipt` with schema, identity, map and result digests, accepted count and cell count. | Checks input/result identity, point alignment, projection accounting and immutable current payload; hashes map, observations and range arrays before receipt. Its `drishti-current-frame-v1` schema is diagnostic and omits future learned/temporal fields. It does not settle the first-release machine consumer or persistence policy. | `tests/test_output.py`, paced CLI test. |
| Version-1 product result/evaluator | `product_result.py`; optional CLI `--evaluate-product-contract` | Actual `ScanFrame` and same-path `FrameResult` -> sealed diagnostic `ProductFrameResult` -> synchronous `ProductReceipt`; future complete producers use the same versioned types. | Exact fields, array dtypes/shapes, canonical SHA-256 and rejection codes are frozen in the [T-002 technical design](../Drishti-2.5/docs/spec-driven/drishti-perception/TECH_DESIGN.md#frozen-t-002-result-and-receipt-version-1) and [decision 0003](decisions/0003-versioned-product-result.md). The evaluator checks payload arrays, point order, pose/provenance, cell nonoverlap and conservative free-beam references. It accepts only sealed bytes-backed arrays; a rejection has no digest or state advance. Diagnostic receipts in report schema 3 are not AC-008 receipts. The complete stage has a 130,000 raw-point cap. | `tests/test_product_result.py`, CLI replay fixture, installed-wheel demo. |
| `ScanFrame` | `contracts.py`; dataset, demo, engine | Sequence, ID, timestamp, Nx4 sensor points, int64 original IDs, 4x4 map pose, pose source, optional annotations. | IDs unique/nonnegative and aligned; transform valid; immutable arrays; ordered frames within engine. | `tests/test_pipeline.py`, `tests/test_dataset.py`. |
| `DatasetSource.frames` | `dataset.py`; CLI | SemanticKITTI `.bin`, `.label`, `calib.txt`, `times.txt`, pose file -> `ScanFrame`. | Six-digit contiguous frame names; matching label size in oracle mode; monotonic times; calibration/pose shape. | `tests/test_dataset.py`; 100-frame real replays of sequences 00 and 08 completed on 2026-09-24. |
| `MappingEngine.process` | `pipeline.py`; CLI/viewer/evaluation | `ScanFrame -> FrameResult`; learned mode requires a point-aligned `SemanticPredictor`. | One sequence per engine; increasing IDs/timestamps; cap `max_points`; learned mode passes only accepted sensor points/IDs to the predictor and never reads oracle annotations; accepted points enter mapping irrespective of projection winner. Point observations include semantic score/unknown reason and timings include model cost. | `tests/test_pipeline.py`, `tests/test_learned.py`, real replay in experiment 0024. |
| FRNet CPU predictor | `learned.py` and isolated `frnet_worker.py`; learned CLI and engine | Hash-pinned checkpoint + safe tensor NPZ + clean pinned upstream source -> accepted-order semantic ID, uncalibrated score and unknown reason. | Host Python 3.12 never unpickles the checkpoint. Worker runs Python 3.8/Torch 1.8, receives accepted points without labels, truncates interpolation to original count and maps channel 19 to unknown ID 0. Hash/revision/count/class/score failures reject. | `tests/test_learned.py`, installed-wheel replay in experiment 0024. |
| Schema-2 semantic result | `product_result.py`; same-process evaluator and learned CLI | Learned `FrameResult` -> sealed semantic-only `ProductFrameResult` -> receipt. | Requires checkpoint/export SHA-256, source/class-map revision and model time. Motion, instances, tracking and free-space remain unknown; this is not an AC-008 complete result. Schema-1 diagnostic behavior remains frozen. | `tests/test_learned.py`, `tests/test_product_result.py`, experiment 0024. |
| Schema-3 obstacle candidate result | `obstacles.py`, `pipeline.py`, `product_result.py`; learned CLI and evaluator | Accepted point-aligned observations -> deterministic frame-local `InstanceEvidence` tuples with original support IDs, observed bounds, class/unknown and ambiguity -> sealed `stage=candidate` receipt. | Explicit `--detect-obstacles` on CPU learned mode; 0.45 m component voxels and 8,192-candidate cap are development settings. Unknown/stuff nonground returns are ambiguous. The evaluator checks support, tight bounds, ordering and absent tracks/beams/occupied/free claims. `--write-panoptic-predictions` writes full input-order raw uint32 labels for offline scoring. Schema 1/2 remain supported. Bounds are observed return envelopes, not solid objects, clearance or navigation proof. | `tests/test_obstacles.py`, real one-scan source/wheel replay, experiment 0028. |
| Schema-4 sequence tracking result | `tracking.py`, `pipeline.py`, `product_result.py`; learned CPU CLI and evaluator | Known observed thing candidates 1..8 plus ordered frame/time/map geometry -> bounded `TrackingUpdate`, immutable `TrackEvidence` and tracking summary -> sealed `stage=tracking` receipt. | `--track-obstacles` requires `--detect-obstacles`; default/max live capacity 512. Two observations confirm; a tentative miss expires; confirmed tracks expire after the third miss. IDs are monotonic within one sequence and are never reused; recent history is bounded at two frames. State commits only after the evaluator accepts the prepared payload; rejection requires a fresh engine replay because native ground state cannot roll back. Velocity/covariance remain unknown. Schema 1-3 digest formats remain supported. `frames.jsonl` carries lifecycle and rejected births, while per-scan panoptic export remains frame-local. | `tests/test_tracking.py`, installed-wheel/source three-scan parity and experiment 0030. |
| Semantic evaluation | `evaluation.py`; offline evaluator | Dataset labels, model prediction files and ranges -> JSON per-class/by-range IoU and unknown coverage. | Dataset and predictions are read-only; full-sequence evaluation requires every matching label file unless partial mode is explicit. Official SemanticKITTI API supplies the canonical full-sequence metric; this module is supplemental. | `tests/test_evaluation.py`, one-scan comparison in experiment 0024 and complete sequence 08 official/range parity in experiment 0025. |
| `Annotations` and class IDs | `semantics.py`; oracle dataset and mapping | Point-aligned uint8 semantic/motion, uint16 instance. | Semantic learning ID 0 unknown/ignored, 1..19 classes; motion UNKNOWN/STATIONARY/MOVING; instance IDs are oracle annotation, not predicted tracks. | `tests/test_semantics.py`. |
| `RangeImage` | `projection.py`; engine and diagnostics | Accepted points/IDs -> pixel winners and collision/outside counts. | Projection is many-to-one; it does not remove non-winners from map. Not free-space evidence. | `tests/test_projection.py`. |
| `MapSnapshot` | `mapping.py`; CLI and Rerun | Immutable per-cell arrays and metadata. | Single frame only; cell ownership nonoverlap; unsupported/ambiguous ground invalid; observed envelopes are not solid occupancy; payload bytes are not RSS. | `tests/test_mapping.py`, `tests/test_visualization.py`. |
| `MappingConfig` | `config.py`; engine/CLI | TOML or defaults -> validated frozen config. | 5 cm base, integer nested sizes, ordered radii, point/coordinate/height and projection bounds, int64 overflow checks. `frame_budget_ms` is a threshold only. | `tests/test_config.py`. |

No tracked database schema, HTTP API, event queue, external service or deployed model interface exists. Future agents must add those here if introduced, with schema version, owner, consumer and migration behavior.
