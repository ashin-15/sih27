What “no data loss” can honestly mean

A one-surface map cannot preserve arbitrary 3D geometry. Require no unexplained point drops, consistent indexing and conservative obstacle preservation. Keep raw scans or multi-surface side storage when reconstruction or faithful bridge/underpass display matters.

Five findings that change the technical decision

1. Tested components are not all in the runtime

The evaluation harness calls dynamic separation, refinement and traversability. The main MapEngine principally shifts, bins, scatters, fuses and clears occupancy. Its binning uses speed 0.0. Evaluation results do not automatically establish the same behavior in the demo.

Code inspection
2. Ignored semantic points become cars

A one-point engine fixture with semantic ID -1 stores candidate 0, the perception convention's car class. Preserve a dedicated unknown sentinel throughout an adapter. The reference was not patched.

Locally reproduced
3. Learned semantics do not mean learned motion

Even with FRNet selected, motion flags are read from dataset labels. The main engine does not use that flag to exclude moving returns from persistent fusion. An autonomous motion path needs separate evaluation.

Code inspection
4. 8.94 MB is a payload number

Default grid arrays including padding occupy 10.92 MB. The engine allocation handle with visibility occupies 87.30 MB; selected extra engine arrays add 46.56 MB. Full runtime and neural-model memory are larger and need peak measurements.

Locally reproduced
5. Legal schedules can exceed refinement capacity

5/10/50 cm is legal. A 50-to-10 cm split needs 25 children, but the default block holds 16. The pool refuses that split. 5/10/20/50 is not a compatible nested hierarchy because its final ratio is 2.5.

The deliverable: a real-time 2.5D dashboard

Show actual variable-size map cells in top-down and tilted views, with terrain/object semantic colors, a legend, optional elevation and dynamic overlays, and a distinct unknown state. Keep geometry, colors and timestamps synchronized. No CRS, geographic map tiles or route planner is required.

Display gap in the reference

Input points can be semantic-colored, but the main occupied-cell renderer uses a height color ramp. Verify that a semantic mode colors the actual 2.5D cells. Show whether classes and motion come from labels or model predictions.

Memory-comparison gap

The live memory graph uses a uniform 2.5D baseline. A separate reduced-footprint 3D comparison exists. The requested dashboard should clearly include the uniform 3D baseline and label calculated versus measured bytes.

A 200 x 200 x 8 m dense volume at 5 cm contains 2.56 billion voxels: 2.56 GB at the reference's occupancy-only 1 byte/voxel assumption. Compared with 10.92 MB of adaptive grid arrays, that is about 234.4x storage-only reduction, not equal-information compression or a full-pipeline speedup.

No working CUDA/data/checkpoint validation was available here. Real accuracy, full-sequence ghost rates, live rendering FPS and peak viewer/model memory remain unverified.
